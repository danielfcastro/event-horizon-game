Do not make the game a pure power fantasy. More mass = stronger pull, larger collision risk, slower precise movement, harder navigation, stability may decay. ## 3. PLAN excerpts this artifact depends on

**5.18 Phase 1 scope:** one black hole; one level; move, attract, absorb, grow. Particles, camera zoom, sound, mass meter, combo are Phase 2 — out of scope.

**5.6 Physics model (arcade, not real astrophysics):**
```text
massGain = bodyMass * efficiency
eventRadius = baseRadius + a * sqrt(mass)
pullStrength = pullScale * mass^0.75
direction = blackHole.pos - body.pos
distanceSquared = direction.lengthSquared() + epsilon
force = pullStrength * bodyMass / distanceSquared
body.velocity += direction.normalized() * force * deltaTime
if distance(body, blackHole) < absorptionRadius: absorb(body)
```

**5.2 Controls:** default mobile drag; camera follows the black hole. Input enters through A-011's intent channel only.

**5.16 Performance:** fixed timestep simulation; object pooling; no allocation in the hot loop.

**Fixed-point spec (A-019 §5):** `FixedQ` = signed 64-bit 32.32 (range ±2^31 WU, resolution 2^-32). No `float`/`double` anywhere in SimCore. `muldiv(a,b,d)` = (a*b)/d via full 128-bit intermediate through 32-bit limbs (Hodgson-style), half-away-from-zero rounding, d==0 hard-asserts. `isqrt(x)` = floor(sqrt(x)) fixed-point aware. Harness self-tests both helpers before any command; `H-01` refuses to start on failure; harness build hashes `Fixed/` and `SimCore/` file sets and fails `FIXED-FORK` on mismatch.

**World units (A-019 §6):** 1 WU = visual radius of starting hole at starting mass (starting hole radius exactly 1 WU). Tables authored in WU. `pixelsPerUnit` is render-only in PlatformBridge, never read by SimCore.

**Snapshot (A-019 §7, format EHSNAP1):** magic "EHSNAP1", ver u16=1, stepIndex i64, seed u64, prng 4×u64, hole 7×i64 (A-019 names six — posX posY velX velY mass radius — but specifies 7 i64s; the seventh is an ambiguity in A-019: decide it is `eventRadius`, document the decision in Snapshot.cs, and keep §7 field order append-only), attractors u16 count + count×i64 radii index order, bodies u16 capacity(300) then per index ascending `u8 flags | i8 category | i8 typeId | posX posY velX velY mass radius (6×i64)`, hazards u16 capacity(24) same record, freeList u16 count + ascending u16 indices, counters (score | stability | combo i64 | absorbedTotal u32 | highmarkSmall/Medium/Large/Hazard u16 | stepsRun, droppedSteps i64), trailing FNV-1a 64 over every preceding byte. All LE, no padding. Every pool index emits a record (inactive = zero record). Golden replay container: `replays/<seed>-<digest8>.json` `{"format":"ehreplay1","seed":"0x…","levelId":"p1-level-01","inputDigest":base64,"snapshots":[{"step":0,"b64":…},{"step":600,…},{"step":-1,…}],"digest8":…,"score":0}` — comparisons are over EHSNAP1 bytes only.

**Digest (A-019 §8, format EIDIG1):** 2 bytes per step: byte0 angle code 0..15 (16-way) or 16=coast; byte1 rate code 0..20 (5% steps, 10=neutral 50%). Digest := magic "EIDIG1", ver u16=1, steps uvarint, RLE pairs {u16 value = byte0<<8|byte1, runLength uvarint>=1}, zero-length runs illegal, sum(runLength)==steps, trailing u64 FNV-1a over magic..last pair. Trailing coast/neutral run trimmed to last non-neutral step. `decode()` total: unknown magic/version/sum/code>16 = hard rejection with named reason, never silent fill.

## 5. A-007 canonical numbers — use these values, do not renumber

Growth constants: `baseRadius = 8.0`, `a = 2.0`, `epsilon = 1.0`, `absorbFactor = 0.30`, `massCeiling = 2^24 = 16,777,216`. Baseline type: `startMass = 100 × T(n)`, `pullScale = 2.0`, `efficiency = 0.85`, `stabilityMax = 100`, `baseSpeed = 26`, `absorbFactor = 0.30`.

```text

eventRadius     = baseRadius + a * sqrt(mass)
pullStrength    = pullScale * mass^0.75         (mass^0.75 = sqrt(mass * sqrt(mass)), two integer sqrt)
```
