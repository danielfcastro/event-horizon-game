## 2. The design rule this artifact must honour — A-019 §10 (verbatim)

> 1. **Time-scale / target-fps knob (A-014 need 4).** `PlatformBridge` exposes
> `dev.targetFps` (60 or 30) and `dev.timeScale` (default 1.0). `timeScale`
> scales the *wall-clock* advance fed to the accumulator and never changes
> `DT = 1/60 s`, so a 30 fps target runs two sim steps per rendered frame
> through the same accumulator and the weak-device path is exercised on a strong
> machine. The knob is reachable from `Runtime/` so the harness can set it
> without Unity, and `PlatformBridge` gates it to non-shipping builds.
> 2. **Quality-tier probe (H-09).** Tiers change render only, never `DT` (A-005).
> The probe returns the selected tier and asserts `SimState` is byte-identical
> across tiers for the same `(seed, inputDigest)`, the regression that keeps a
> quality setting out of difficulty.
>
> `FixedStepDriver` asserts `DT` is the constant `1/60` every step and that
> `droppedSteps` only grows through the `MAX_CATCHUP = 4` rule; a `timeScale`
> implying another `DT` is rejected at startup, so no test can measure a
> different simulation.

A-005 §3.2 is the frame-driven loop: `accumulator += frameDelta`,
`while accumulator >= DT and steps < MAX_CATCHUP: step()`, then
`alpha = accumulator / DT` as a **render-only** interpolation factor.

A-019 §9 command forms (the exact CLI surface):

| H-06 | `harness hitch --at 120,341,902 --ms 42` injects deterministic hitches into the frame driver, not into SimCore | S-09, P-11 |
| H-07 | `harness fps --target 30 [--time-scale 2.0]` forces the 30 fps step budget on a strong machine | P-02, P-10 |
| H-08 | `harness pointer --script @file` injects synthetic pointer events into `InputAdapter` (A-014 T2) | I-*, U-* |
| H-09 | `harness tier --probe` reports the quality tier the device selects and asserts it changed render state only | P-* tier checks |

A-019 §9 availability note, verbatim: "H-06 perturbs the frame driver only, so
an injected hitch changes `droppedSteps` and nothing else, which is the S-09 /
P-11 assertion." A-019 §10 already says `droppedSteps` "only grows through the
`MAX_CATCHUP = 4` rule", so a hitch smaller than the catch-up budget does NOT
grow `droppedSteps`; the precise assertion is recorded in `PLAN.md` §A-022 and
must be printed by the command, not assumed.

A-019 §9 also says P-10 keeps a hardware-only component and "its record carries
`hardware-only: true`, visibly split rather than silently skipped" — H-07's
record must carry that flag.

## 3. Upstream decisions already made (do not re-decide)

- `DT = 1/60` is `FixedStepDriver.DT = 71582788L` Q32.32 raw, asserted every
  step; `MAX_CATCHUP = 4`; the dropped-step rule consumes one step's debt per
  hitching frame and never simulates late.
- `PlatformBridge` owns `devTargetFps` / `devTimeScaleRaw` and `configureStartup()`
  delegates the rejection to `FixedStepDriver.configureStartup`; phase 1 accepts
  `timeScale == 1.0` only, so `--time-scale 2.0` MUST be a startup rejection
  (exit 2, harness error), never a pass.
- `pixelsPerUnit` is render-only and "nothing in SimCore reads it; art
  rescaling cannot invalidate a golden replay" (A-019 §6).
- Input is quantized to steps: one code pair per DT tick, never per-frame raw
  pointers (A-011). `InputAdapter` is transport only and holds no input scheme.
- Exit codes (A-019 §9): 0 pass, 1 fail, 2 harness error. `main.cs` catches
  `SystemicFailure` and returns 2 — a startup rejection is a harness error.
- FIXED-FORK hashes exactly the 19 files enumerated in `main.cs` (`Fixed/` +
  `SimCore/`); `tools/harness/` and `Bridge/Unity/` are NOT hashed.

## 4. Open questions this artifact must answer

1. Where does the frame driver live so BOTH the Unity entry and the harness
   reach it, and so that it is not a hashed file? (`Bridge/Unity/` holds the
   bridge layer; `InputAdapter`, `LevelLoader`, `PlatformBridge` already
   compile headless there.)
2. How does a frame deliver per-step intents when `advance` carries one intent
   per frame? (Answered in `PLAN.md` §A-022: add `advanceDigest` in `FixedStepDriver`
   sharing one `deliver`; `InputDigest.decode` is already in `SimCore`.)
3. What can the tier probe honestly report with no device in this environment?
   (It must not fabricate a tier; the device-derived selection belongs to A-023.)
4. What does a synthetic pointer script contain, given `InputAdapter` is
   transport only and A-011 owns the pointer→intent scheme?

## 6. Verified facts about the existing code (do not re-derive)

- `FixedStepDriver.step(s, stepIndex, i)` hard-asserts `s.dt == DT`,
  `stepIndex == s.stepIndex`, and `s.intent == i`; then `SimStep.run`, then
  `s.stepIndex += 1`.
- `FixedStepDriver.advance(s, wallDeltaRaw, i)` accumulates, runs at most
  `MAX_CATCHUP` steps, drops further debt into `s.droppedSteps`, returns steps
  executed.
- `Commands.runLoop(s, dg, interval, steps, blobs, out snapCount)` is the ONE
  step-driven harness loop: `InputAdapter.sampleFromDigest(dg, s.stepIndex)` →
  `s.intent = i` → `SpawnDirector.apply(s)` → `FixedStepDriver.step(...)`.
  Goal check `(s.holeMass >> 32) >= LevelTable.targetMass`; `maxSteps =
  LevelTable.timerSeconds * 60`.
- `emitSnapshot(s)` (in `Commands.cs`) produces the canonical `EHSNAP1` blob.
- `LevelTable`: `levelId = "p1-level-01"`, `defaultSeed = 0x1F4A`,
  `targetMass = 1000`, `timerSeconds = 155`.
- Golden fixtures: `replays/p1-level-01.digest.bin` (EIDIG1) and
  `replays/p1-level-01.json`; H-01 prints `digest=6d25ff0add639448 steps=2828
  droppedSteps=0 result=goal exit=0`.
- `Intent` is a class in `SimState.cs` (`thrustX`, `thrustY`, `rate` Q32.32).
- `InputDigest.decode(byte[] data, long step)` is pure and cursor-free;
  `InputAdapter.sampleIntent(stepIndex)` asserts a monotonic cursor (live path).
- `fileRecord(result)` writes `artifacts/harness/<runId>/<testId>.json` and
  hardcodes `"hardwareOnly": false`.
- Build: `dotnet build harness.csproj -o obj`, run `dotnet exec obj/harness.dll
  <args>`; `harness.csproj` globs `Assets/**/*.cs` excluding exactly
  `GameLoop.cs`, `RenderLayer.cs`, `UIRoot.cs`, so a new `Bridge/Unity` file
  compiles headless automatically.
