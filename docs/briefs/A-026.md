**Acceptance criteria (all must be met with evidence, none may be assumed):**

1. A window opens on the desktop and shows the hole and the bodies.
2. Keyboard thrust moves it through the same 16-way `InputDigest` angle table the
   replay channel uses; `holeMass` and `holeRadius` grow as bodies are absorbed.
3. The run reaches the `p1-level-01` goal at the same step index as H-01 (**2828**).
4. The renderer READS `SimState` and never writes to it; the simulation is the
   existing `SimCore`/`FixedStepDriver` reached through `FrameDriver.frameLive`,
   not a reimplementation.
5. A frame payload dumped from the client matches the harness snapshot at the same
   step index (byte-exact).
6. The C renderer compiles with `gcc -lSDL2`; the C# side builds with 0 errors and
   0 warnings; `DT` stays `71582788L`.

## 2. Design rule (PLAN.md §8, verbatim in effect)

- One simulation. A renderer never re-implements stepping and never writes state.
- Never report a gate green without evidence. Never fake success.
- Never write code that does not follow the approved architecture, design, and
  balance documents.
- `pixelsPerUnit` is render-only and never read by `SimCore` (A-019 §6).
- No float/double in the simulation path.

## 3. Design decisions already recorded in PLAN.md §A-026 (honour them, do not re-decide)

- **Two processes, one simulation** — forced, not chosen: this .NET 8 toolchain
  cannot call a C library from C#. Probed: `#pragma DLI_Import` → `CS1633
  Unrecognized #pragma directive`; `extern "C"` → `CS1003 'alias' expected`.
- **Renderer reads `SimState`, never writes it.** The sim side reaches the run
  through `FrameDriver.frameLive(clock, state, intent)`; the exactly-one-loop rule
  of A-019 §11 still holds; no stepping code is duplicated.
- **Live input uses the same quantization as the replay channel.** A key selects
  one of the 16 direction codes of `InputDigest.ANGLE_X/ANGLE_Y` (16 = coast);
  the `Intent` is built from that table. Pointer-position → intent resolution is
  A-011's and stays OUT of scope.
- **Exchange is by file, atomically, never by pipe.** The sim writes the newest
  frame payload to a temp file and renames it into place; the renderer reads
  whatever complete payload is newest. A pipe would stall the sim whenever the
  renderer has not consumed a frame.
- **The payload is observable state, not a render product.** Step index, hole
  position/radius/mass, active bodies, `pixelsPerUnit`, result flag, plus the
  canonical snapshot bytes for that step.
- **`pixelsPerUnit` stays render-only.** Camera follows the hole; WU → px happens
  in the renderer. `DT` untouched.

### Build facts already proven in this repo (do not re-probe, do not "simplify")

- Root `harness.csproj` with root-relative globs is the verified build shape; globs
  resolve relative to the **csproj**. `EnableDefaultCompileItems` must be `false`
  (default true + explicit `<Compile>` → `NETSDK1022` duplicate-Compile failure).
- With default items off, the `<Compile>` element's **`Exclude` attribute** works;
  the `<Exclude>` **element** form is inert.
- Build: `dotnet build harness.csproj -o obj`; run `dotnet exec obj/harness.dll …`
  (the native launcher `./obj/harness` exits 131; `dotnet run` masks the app exit
  code when piped). `DOTNET_ROOT=$HOME/.local/dotnet`, `PATH=$PATH:$HOME/.local/dotnet`.
- Grep build output with `error|warning|Build` — filtering `error CS` hides
  project-level failures AND warnings.
- `System.IO.File.ReadAllBytes/ReadAllText/WriteAllText` and
  `System.IO.Directory.CreateDirectory` are available; `Directory` exposes no
  List/Walk.
- `fixed` is a reserved word in C#.
- FIXED-FORK hashes exactly the 19 files under `Fixed/` + `SimCore/`. `tools/` and
  `Bridge/Unity/` are NOT hashed. Adding files there cannot invalidate a golden;
  editing `Fixed/` or `SimCore/` requires re-blessing `forkExpected`.
