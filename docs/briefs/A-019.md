## PLAN.md section 8 — design rule (verbatim)

Do not make the game a pure power fantasy.

```text
more mass = stronger pull
more mass = larger collision risk
more mass = slower precise movement
more mass = harder navigation
more mass = stability may decay
```

The scaffold must not contain any affordance that softens this tension (no assists,
no catch-up mechanics, no stat buffers). The rule constrains values, not slots: the
scaffold may stub slots without values.

## Upstream: A-005 docs/architecture.md (approved) — excerpts you must honor

Platform: Unity 2D + C# + URP; primary target Android phone; secondary iOS (same
project, build-target switch); dev/QA target desktop standalone. Layering:

```text
Assets/
  Runtime/   simulation core (pure C#, no Unity API calls)
  Bridge/    Unity MonoBehaviour layer: render, input, UI, platform
  Data/      data-driven tables
```

Decision honored by all code: the simulation core has zero Unity API dependencies, so
it can be re-simulated headless on desktop.

Module tree (SimCore, deterministic, headless-capable): FixedStepDriver, PRNG,
SpatialHash, PlayerController, AttractionSystem, AbsorptionSystem, HazardSystem,
GrowthSystem, StabilitySystem, ComboSystem, ScoringSystem, SpawnDirector, BodyPool,
InputDigest. Non-simulation: LevelLoader, RenderLayer, InputAdapter, UIRoot, MetaLayer,
PlatformBridge.

Module contracts: every SimCore subsystem is a pure function of `(state, stepIndex,
intent)`; no wall clock, no Unity API, no unordered-iteration reads. HazardSystem
exposes only `applyInfluence(body, hazard)` and `onContact(body, hazard)`. Stability/
Combo/Scoring expose slots, not values (A-007 fills them).

Attraction (PLAN 5.6, per body, fixed attractor-index order):

```text
direction = blackHole.pos - body.pos
distanceSquared = direction.lengthSquared() + epsilon
force = pullStrength * bodyMass / distanceSquared
body.velocity += direction.normalized() * force * dt
```

Absorption: `if distance(body, blackHole) < absorptionRadius: absorb(body)`, once per
step. Bodies do not collide with each other.

Fixed timestep: DT = 1/60 s; frame-driven loop with accumulator; `MAX_CATCHUP = 4`
steps per frame; dropped catch-up steps discarded (no time credit); `alpha` is render-only
interpolation. Quality tiers change render only, never DT.

Determinism rules:
1. Fixed-point 32.32 (signed 64-bit) for positions, velocities, mass, force; `isqrt`
   on fixed-point mass for `eventRadius = baseRadius + a*sqrt(mass)`; mul/div via two
   64-bit muldiv helpers "implemented in A-019".
2. PRNG: splitmix64 seeds xoshiro256+; one stream per level, `seed = hash(levelId,
   sessionSeed)`.
3. Input quantized to steps: per-step fixed-point intent sampled once per step, not
   per render frame; InputDigest is the array of per-step intents.
4. Iteration order is index order; SpatialHash queries return index sets processed in
   ascending index order.

Reproducibility: a run is fully identified by `(sessionSeed, inputDigest)`; headless
re-sim yields the same score on any device. Leaderboard entry stores seed, score,
inputDigest (run-length encoded per-step intents), and a run hash (FNV-1a over final
sim state).

Data structures: BodyPool SoA, capacity 300 (small <= 220, medium <= 56, large <= 24),
plus <= 24 static hazard entities in a separate pool; fields active/category/typeId/
posX/posY/velX/velY/mass/radius/flags + freeList. All preallocated at boot; zero
allocation in the hot loop. Attractor list <= 32 entries, player always index 0.
Spatial hash: uniform grid, cellSize = sqrt(worldArea / N), counting-sort rebuild per
step. Tables: ObjectTable {typeId, category, mass, radius, absorbable, hazardFlags};
LevelTable {seed, worldBounds, spawnEvents}. The prototype consumes the same tables
with one entry each.
